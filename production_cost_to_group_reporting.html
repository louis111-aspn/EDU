Section 01
생산오더 원가정산 프로세스

월말 결산 시 생산오더의 원가를 확정·배부하는 3단계 핵심 트랜잭션. 선후 관계를 위반하면 FI/CO 데이터 왜곡이 발생한다.

①
KKAX — WIP 계산
미완성 오더(REL 상태)의 재공품 금액을 산출. FI 전표 미발생 — 순수 시뮬레이션 단계. Test Run으로 오류 검증 후 본 실행 필수.
②
KKS2 — 분산 계산
완료 오더(DLV/TECO)의 표준원가 vs 실제 투입원가 차이를 산출. 선택 실행이나 TECO 오더 존재 시 KO88 전 반드시 선행.
③
KO88 — 오더 정산
오더 잔액을 수신 객체로 배부·클리어. 실제 FI/CO 전표를 생성하는 종착지. 정상 마감 시 오더 잔액은 원칙적으로 0이어야 한다. (Settlement Rule 오류·Variance 미정산·RA 잔액 등으로 잔액이 남을 수 있으므로 반드시 사후 검증 필요)

Section 02
GR · SAC-P 컨설턴트가 이해해야 할 업무 맥락

KO88은 CO 컨설턴트만의 트랜잭션이 아니다. GR·SAC-P 컨설턴트가 이 프로세스를 이해해야 하는 이유를 역할별로 정리한다.

왜 알아야 하는가
KO88이 완료되지 않으면 개별 법인의 원가 관련 계정 잔액이 미확정 상태로 남는다. 이 상태에서 GR이 데이터를 수집하면 연결 조정의 기초 데이터 신뢰성이 훼손되고, SAC-P가 실적 데이터를 수신하면 계획 대비 분석(Actual vs. Plan)이 오염된다. KO88 완료는 상위 시스템 전체의 데이터 신뢰성을 보장하는 게이트키퍼다.
📊 SAC-P 컨설턴트 관점

① 데이터 인터페이스 시점 통제

S/4HANA 실적 데이터를 SAC-P로 전송하는 스케줄은 반드시 KO88 완료 시그널 이후로 동기화되어야 한다. 위반 시 미확정 원가가 수익성 리포트에 반영되어 경영진 의사결정을 왜곡한다.

설계 원칙
SAC-P 데이터 로드 배치 → KO88 완료 이벤트를 트리거로 설정할 것. 일정 시간 기준 스케줄보다 이벤트 기반 연동이 안전하다.

② 수익성 예측 모델 드라이버

KO88으로 확정된 원가 분산(Variance) 데이터는 SAC-P의 수익성 계획 모델에서 미래 원가 상승률 및 생산 효율성 시뮬레이션의 핵심 입력 드라이버로 활용된다.

🏢 Group Reporting 컨설턴트 관점

① 개별 시산표 확정의 게이트키퍼

KO88이 누락되면 원가 관련 계정 잔액이 미확정 상태로 남아 개별 법인 시산표의 신뢰성이 훼손된다. GR 데이터 수집(Data Collection / Release) 전 개별 법인의 원가 마감 완료 여부를 통제하는 것은 GR 컨설턴트의 필수 체크포인트다.

② 미실현 손익 제거의 기초 소스

KKAX/KO88으로 확정된 기말 재공품(WIP) 및 재고 금액 내부에는 관계사 간 유통 마진(Intercompany Markup)이 포함되어 있다. 이를 파악하여 연결 조정 분개 시 미실현 이익을 제거하는 기초 소스로 활용해야 한다.

⚠ 실무 함정
KO88 미실행 상태에서 GR이 데이터를 수집하면, 원가 관련 계정 잔액이 미확정인 채로 연결 조정이 시작된다. 이후 법인이 재마감하면 GR 데이터와 차이가 발생하며 조정 공수가 급증한다.

Section 03
Group Valuation 설정 및 작동 프로세스

자재원장(ML) 기반 Parallel Valuation 구조로 Legal과 Group 두 개의 평가 뷰를 병렬 기록하는 원리. 설정 체계의 개념부터 STO 거래 기준 실제 분개 비교까지 해설한다.

5-1. 개념 구조: 3개의 Valuation View

Valuation View목적기준 가격사용 주체
Legal 개별 법인 재무제표 (세법·공시) 이전가격 (Transfer Price) 각국 국세청, 감사인
Group 연결 재무제표 (내부거래 제거) 제조원가 (Cost of Production) 그룹 CFO, GR 연결팀
Profit Center 사업부 수익성 관리 PC 간 내부 정산가 경영관리팀, SAC-P
핵심 원리
동일한 STO 거래에 대해 Legal View에는 이전가격(예: 120)이, Group View에는 제조원가(예: 100)가 기록된다. 그 차이 20이 연결 조정 대상 미실현 이익이다. Universal Journal(ACDOCA)에서 Valuation View별 금액은 Ledger·Currency Type·Valuation View의 조합으로 별도 관리되며, 실제 필드 구조는 시스템 릴리즈 및 설정에 따라 다를 수 있다.

5-2. 사전 요건 (Prerequisites)

ML은 Group Valuation의 필수 전제입니다. ML 없이 Group Valuation은 작동하지 않습니다. Plant 레벨에서 활성화하며, 한번 활성화 후 비활성화 불가(Irreversible)입니다.

SPRO → Controlling → Product Cost Controlling → Actual Costing/Material Ledger → Activate Valuation Areas for Material Ledger
Currency Type코드용도예시
Company Code Currency10개별 법인 기능통화KRW
Group Currency30연결 기준 통화USD
Hard Currency / Index40인플레이션 국가 대응선택사항
⚠ 설정 누락 시
Currency Type 30(Group)을 할당하지 않으면 Group Valuation 데이터가 ACDOCA에 생성되지 않는다.

S/4HANA Universal Journal(ACDOCA) 기준으로 Leading Ledger(0L)에 Legal Valuation이 기록됩니다. Group Valuation 금액은 Valuation View별로 별도 관리되며, 실제 분리 방식(Ledger·Currency Type·Valuation View 조합)은 시스템 릴리즈 및 설정에 따라 다를 수 있습니다. 프로젝트 착수 시 해당 시스템의 ML 설정을 먼저 확인하는 것이 선행되어야 합니다.

3. 설정 체계 개요 (Configuration Overview)

아래 4단계는 Group Valuation 구현에 필요한 설정 영역의 개념적 순서다. 각 단계의 실제 SPRO 경로와 화면은 시스템 버전·ML 구성·Transfer Pricing 시나리오에 따라 달라지므로, 실제 프로젝트에서는 SAP Note 및 해당 릴리즈 IMG를 반드시 병행 확인해야 한다.

1
ML Type 설정
Currency Type 10·30 할당
SPRO → Controlling → Product Cost Controlling → Actual Costing/Material Ledger → Assign Currency Types to Material Ledger Type
ML Type에 Legal(10), Group(30) Currency Type을 할당. 미할당 시 Group 데이터 미생성.
2
Parallel Valuation / Group Valuation 활성화
Material Ledger 기반 병렬 평가 체계 설정
개념 먼저 이해
Group Valuation은 SAP Group Reporting의 기능이 아니다. 정확히는 Material Ledger(ML) 기반 Parallel Valuation의 일부로, Transfer Pricing 시나리오를 위해 설계된 기능이다. "GR을 구축하면 자동으로 쓸 수 있는 기능"이라는 오해가 프로젝트 현장에서 자주 발생하므로 주의가 필요하다.

활성화 경로는 SAP 릴리즈(On-Premise EHP 버전 / S/4HANA Cloud / Private Cloud)와 ML 설정 구성에 따라 다르며, 일반적으로 Controlling → Product Cost Controlling → Actual Costing/Material Ledger 체계 안에서 Parallel Valuation 옵션을 활성화하는 방식으로 구성된다. 특정 SPRO 경로를 단정하기보다 해당 시스템의 ML Type 및 Valuation Profile을 먼저 확인해야 한다.

활성화 즉시 해당 Plant/Company Code의 모든 재고 이동에 Group View 평가금액이 Legal과 병렬로 기록된다.

5. Universal Journal(ACDOCA) 기록 구조 — 개념 참고

Group Valuation이 활성화된 경우, 동일 거래에 대해 Legal View와 Group View의 금액이 Universal Journal 내에서 별도 Valuation View로 관리된다. 실제 저장 방식(관련 필드, Ledger 구성, Currency Type 매핑)은 Transfer Pricing 활성화 여부, SAP 릴리즈, Valuation Profile 설정에 따라 다르다.

⚠ 프로젝트 착수 시 반드시 확인
특정 필드값(예: VALUATIONCATEGORY, CURTYPE 등)을 단정하여 조회 조건으로 사용하면 고객 시스템과 맞지 않을 수 있다. 반드시 해당 시스템의 ML Type 설정 → Valuation Profile → Parallel Valuation 구성을 먼저 확인한 후 조회 조건을 수립해야 한다.
Legal Valuation View
개별 법인 이전가격(Transfer Price) 기준 금액. 각국 세법·공시 기준 장부의 근거가 되는 데이터.
Group Valuation View
제조원가(Cost of Production) 기준 금액. 법인 간 내부 마진이 제거된 뷰이며, 연결 수익성 분석의 기초 데이터로 활용된다.
조회 접근 방법
ACDOCA에서 두 Valuation View의 금액 차이를 비교하면 법인 간 내부 마진 규모를 파악할 수 있다. 단, 실제 조회 필터 조건은 해당 시스템의 ML 설정을 확인한 후 수립해야 하며, 특정 필드값을 사전에 단정하지 않도록 주의한다.
Section 04
Group Valuation 도입 시 고려사항 및 운영 난이도

Group Valuation은 SAP 표준 기능으로서 유효하다. 다만 대규모 글로벌 제조기업 외에는 운영 복잡성으로 인해 채택 사례가 제한적이다. 도입 전 검토해야 할 4가지 고려사항을 정리한다.

기능의 가치
자재원장(ML) 기반으로 관계사 간 거래의 내부 마진을 자재 코드 레벨에서 실시간 분리·기록한다. 추정치가 아닌 실제 물류 흐름 데이터이므로 완전한 Audit Trail이 확보되어 외부 감사 대응력이 높다. 조건이 갖춰진 기업에서는 연결 결산 자동화의 핵심 기반이 된다.

Group Valuation 도입 가치가 높은 기업 프로파일

운영 난이도 검토 전에, Group Valuation이 실질적인 가치를 발휘하는 기업 조건을 먼저 확인한다. 아래 항목에 해당할수록 도입 효과가 크다.

비즈니스 특성
✓ 글로벌 제조·판매 법인 간 재고 이전(STO) 거래 비중이 높음
✓ Transfer Pricing 이슈가 세무·공시 측면에서 중요하게 관리됨
✓ 실시간 연결 손익 파악이 경영 의사결정에 필수적
✓ 법인 간 제품 믹스(Product Mix) 변동이 크고 평균 마진율 추정이 불정확
운영 인프라 조건
✓ 전사 S/4HANA 환경 표준화 완료 (공급망 법인 포함)
✓ D+3~5일 내 연결 마감을 시스템으로 달성해야 하는 요건
✓ 자재원장(ML) 실제원가 계산 체계가 이미 안정적으로 운영 중
✓ MDM 거버넌스 조직이 존재하여 이전가격 마스터를 상시 관리 가능
컨설턴트 진단 시작점
위 조건 중 비즈니스 특성 2개 이상 + 운영 인프라 조건 3개 이상이 충족된다면 Group Valuation Full 도입을 진지하게 검토할 수 있다. 그렇지 않다면 아래 운영 난이도 요인을 먼저 점검하고 Section 05의 SAC-P 대안 아키텍처를 우선 고려한다.

4가지 운영 난이도 요인

01
글로벌 ERP 통합 범위
공급망 내 법인들이 서로 다른 ERP를 사용하는 경우 실시간 마진 추적 체인이 단절될 수 있다. 전 법인이 단일 S/4HANA 환경으로 통합되어 있을수록 Group Valuation의 효과가 커진다.
02
ML 마감 순서와 일정 압박
법인 간 원가 마감 릴레이(본사 → 해외 제조 → 판매법인)가 완료되어야 최종 그룹 마진이 확정된다. 마감 일정이 촉박한 환경에서는 이 릴레이 지연이 연결 마감 일정에 영향을 줄 수 있다.
03
Legal·Group 이중 검증 부담
각국 세법은 법적 실체 기준 장부(Legal Valuation)만 인정한다. Group View를 병행 운영하면 재무팀이 두 개의 장부를 동시에 검증해야 하므로 결산 업무 부담이 증가한다. 조직 역량과 프로세스 설계가 선행되어야 한다.
04
기준정보(Master Data) 유지 체계
법인 간 이전가격과 내부 마진 요소를 구매정보레코드(PIR) 등에 지속적으로 최신화해야 정확한 Group View가 산출된다. MDM 거버넌스와 담당 조직이 갖춰지지 않으면 데이터 품질이 빠르게 저하된다.

실제 활성화 사례 유형

유형대상 기업 특성실제 운영 방식
유형 1
글로벌 단일 인스턴스		 전 세계 법인이 하나의 S/4HANA 환경으로 통합된 대규모 글로벌 제조기업 Group Valuation View 실시간 운영 가능

혼합 운영 기능을 활성화했으나 데이터 정합성 이슈가 발생하는 경우 시스템 데이터와 별도 검증 마진율을 병행 사용하는 하이브리드 운영. 완전 자동화까지 추가적인 거버넌스 정비가 필요하다.
컨설턴트 진단 접근법
고객이 Group Valuation 도입을 검토할 때, 위 4가지 운영 난이도 요인 중 몇 개가 이미 갖춰져 있는지를 먼저 진단한다. 다수 요인이 미충족 상태라면 중장기 로드맵으로 전환 조건을 명시하고, 단기적으로는 Section 05의 SAC-P 대안 아키텍처를 제안하는 것이 현실적이다.
Section 05
SAC-P 기반 대안 아키텍처

ERP 자재원장의 부하 없이 SAC-P의 계산 엔진을 활용하여 경영관리 목적의 연결 수익성을 시뮬레이션하는 현실적 대안. SAC-P는 연결회계 엔진이 아니므로 이 아키텍처의 결과물은 법적 연결 재무제표가 아닌 경영관리용 연결 수익성 분석임을 명확히 구분해야 한다.

딜레마
임의 추정 마진율 업로드 방식은 제품 믹스(Product Mix) 왜곡, 물류 경로 추적 불가, 제조 원가 분산(Variance) 실종을 유발한다. Group Valuation이 아키텍처상 더 정확하지만, CFO 입장에서는 적시 공시와 세무 안정성이 우선이므로 운영 복잡도가 높은 Group Valuation을 즉시 도입하기 어려운 상황이 많다.

전체 아키텍처 플로우

1
S/4HANA — 개별 법인
KO88 정산 완료 후 법인별 실제 원가·매출 전송
법인 간 재고이전(STO) 물류 흐름 정보(출발-도착-품목그룹)를 함께 매핑하여 SAC-P로 전달. Live Connection(SAP_COM_0065) 또는 배치 전송.
2
SAC-P — 연결 경영관리
거래 관계 마스터화 + 경영관리 목적 연결 수익성 시뮬레이션
[출발-도착-품목그룹별] 실제 거래 관계를 마스터 데이터로 구성. Allocation Step + Data Action을 통해 품목 레벨 내부 마진을 차감한 경영관리 목적 연결 수익성 뷰를 산출한다. 법적 연결 재무제표와는 별도로 관리되어야 한다.
3
최종 아웃풋
인과관계가 확보된 시스템 기반 연결 수익성 보고서
품목별·노선별 연결 수익성 분석(CO) 데이터를 경영진에게 적시 제공. 엑셀 추정치 대비 인과관계 추적 가능.

SAC-P 핵심 기능 — Allocation Step 설계

SAC-P의 Allocation Step은 특정 기준에 따라 금액을 자동 배부하는 계산 단계다. 미실현 이익 제거에는 아래 2단계 Allocation을 순차 실행한다.

Step A — 마진율 테이블 적용

STO 거래별 실제 마진율을 SAC-P 마스터 테이블에 로드하고, 해당 마진율을 법인별 재고 금액에 곱하여 경영관리 목적의 내부 마진 차감 금액을 산출한다. 이는 회계적 미실현 이익 제거(연결조정 분개)와는 구분되는 관리회계 계산이다.

Allocation Step A: Source: 재고(Inventory) × 마진율(Markup%) Driver: [출발법인 × 품목그룹 × 도착법인] Target: 미실현이익 계정 (Unrealized Profit) Method: Override (마스터 테이블 참조)
Step B — 경영관리 연결 P&L 재구성

Step A에서 산출된 내부 마진을 경영관리 P&L에서 차감하고, 법인 간 내부 매출·매입을 상계하여 외부 매출 기준 연결 수익성을 완성한다. 법적 연결 재무제표는 GR에서 별도 생성되며, 이 결과물은 경영관리 보고 전용이다.

Allocation Step B: Source: 미실현이익 (Step A 결과) Action: Group P&L에서 차감 IC Revenue / IC COGS 상계 Output: 연결 수익성 (External View)

SAC-P Data Action 설계 예시

Data Action은 SAC-P Planning Model 내 데이터를 조건부로 읽고 쓰는 스크립트 엔진이다. 아래는 경영관리 목적 내부 마진 차감 로직의 구성 예시이며, 회계적 연결조정 분개와는 별도로 관리되어야 한다.

// Data Action: IC_Margin_Adjustment_for_Management_Reporting // 목적: 경영관리 목적 연결 수익성 시뮬레이션 (법적 연결조정 아님) // 실행 시점: 매월 KO88 완료 이벤트 후 자동 트리거 // Step 1. STO 재고 잔액 조회 DATA lv_inventory = READ(Account = "INVENTORY", Entity = [Sender_Entity], Product = [Product_Group], Version = "ACTUAL") // Step 2. 마진율 마스터 참조 DATA lv_markup_rate = LOOKUP(Table = "IC_MARKUP_MASTER", Key = [Sender + Receiver + Product_Group]) // Step 3. 내부 마진 차감 금액 계산 및 기록 (경영관리 뷰) WRITE(Account = "IC_MARGIN_ADJUSTMENT", Entity = [Consolidated], Value = lv_inventory * lv_markup_rate * -1, Mode = "OVERRIDE") // Step 4. IC 매출·매입 상계 (경영관리 목적) WRITE(Account = "IC_REVENUE_MGMT", Value = READ(Account = "IC_REVENUE") * -1) WRITE(Account = "IC_COGS_MGMT", Value = READ(Account = "IC_COGS") * -1)
기대효과
① 결산 속도: ERP 자재원장(ML) 부하 없이 SAC-P 엔진만으로 경영관리 연결 수익성 보고 가능 — 더 빠른 마감 일정 달성
② 분석 정교성: 수작업 엑셀 평균 마진율 대비 품목별·노선별·법인별 인과관계 추적 가능한 경영관리 데이터 제공
③ 거버넌스: IC_MARKUP_MASTER 테이블 단일 통제로 마진율 업데이트 공수 최소화
⚠ 구분 주의: 이 결과물은 경영관리 보고용이며, 법적 연결 재무제표는 SAP Group Reporting에서 별도 생성된다.

Key Take Away
Group Valuation은 연결조정을 제거하는 기능이 아니라,
연결조정을 사전에 예방하기 위한 운영 모델이다.
대부분 기업의 현실
SAP Group Reporting 기반 사후 연결조정 방식을 선택한다. 운영 복잡도가 낮고 세무 안정성을 확보하면서도 K-IFRS / IFRS 연결 재무제표 요건을 충족할 수 있다.
Group Valuation의 위치
높은 운영 성숙도(전사 ERP 표준화, MDM 거버넌스, ML 안정화)를 갖춘 기업을 위한 고급 아키텍처다. 도입 자체가 목적이 아니라, 조건이 갖춰진 후의 자연스러운 진화 단계로 봐야 한다.
