01
Foundation
현금흐름표 기초
재무제표 내 위상

현금흐름표는 재무상태표(B/S), 손익계산서(P&L), 자본변동표와 함께 4대 재무제표 중 하나입니다. K-IFRS 1007호 / IAS 7에 따라 모든 상장기업은 작성이 의무입니다.

핵심 역할
P&L이 이익을 얼마나 냈는가를 보여준다면, 현금흐름표는 실제 현금이 어디서 들어오고 어디로 나갔는가를 보여줍니다. 흑자도산의 원인 진단에 필수적입니다.
IAS 7 / K-IFRS 1007 핵심 요건
  • 현금흐름은 영업 · 투자 · 재무 3분류로 구분 표시
  • 영업활동: 직접법 또는 간접법 선택 가능 (IAS 7은 직접법 권장)
  • 투자 · 재무활동: 원칙적으로 총액(Gross) 표시
  • 외화 현금흐름: 거래일 환율 적용, 환율변동효과 별도 표시
  • 이자 · 배당 수수: 일관된 분류 정책 적용 및 공시
현금흐름 3분류 구조
① 영업활동 (Operating)

기업의 주된 수익 창출 활동 및 투자·재무 활동에 해당하지 않는 거래에서 발생한 현금흐름

  • 고객으로부터의 현금 수취
  • 공급자·종업원에게 지급
  • 법인세 납부
  • 이자 수취·지급 (정책에 따라)
② 투자활동 (Investing)

장기성 자산 및 타 기업 투자의 취득·처분에서 발생한 현금흐름

  • 유형자산 취득·처분
  • 무형자산 취득
  • 지분증권·채무증권 취득·처분
  • 대여금 지급·회수
③ 재무활동 (Financing)

자본 및 차입금의 조달·상환에서 발생한 현금흐름

  • 주식 발행·자기주식 취득
  • 차입금 차입·상환
  • 리스부채 상환 (IFRS 16)
  • 배당금 지급
⚠ 분류 판단이 중요한 이유
이자수취는 영업 또는 투자, 이자지급은 영업 또는 재무, 배당수취는 영업 또는 투자로 각각 분류 가능합니다. 기업은 최초 선택 후 일관성 있게 적용해야 하며, 이 선택이 SAP 계정 매핑 설계에 직접 영향을 미칩니다.
02
Methodology
직접법 vs. 간접법 — 방법론 비교

두 방법의 차이는 영업활동 현금흐름 계산 방식에만 존재합니다. 투자·재무활동은 두 방법 모두 동일하게 작성합니다.

직접법 (Direct Method)
개념

현금 유입과 현금 유출 항목을 원천별로 직접 집계하여 표시. 실제 현금거래 계정의 합산.

산식 구조
고객으로부터 수취한 현금
(-) 공급자에게 지급한 현금
(-) 종업원에게 지급한 현금
(-) 기타 영업관련 지급
(±) 이자·법인세 현금흐름
─────────────────────────
= 영업활동 순현금흐름
장점
  • 정보 이용자가 현금흐름의 원천을 직관적으로 파악
  • IAS 7이 권장하는 방법
  • 미래 현금흐름 예측력 우수
단점
  • 발생주의 기반 ERP에서 추출 복잡
  • 추가 계정 설계 또는 원천 데이터 태깅 필요
  • 구현 비용 상대적으로 높음
간접법 (Indirect Method)
개념

당기순이익에서 출발하여 비현금 항목 조정 + 운전자본 증감을 통해 역산하는 방법.

산식 구조
당기순이익
(+) 비현금 조정: 감가상각비, 충당부채 전입
(-) 비현금 조정: 자산처분이익 등
(±) 운전자본 증감:
    매출채권 증감, 재고 증감
    매입채무 증감 등
─────────────────────────
= 영업활동 순현금흐름
장점
  • 발생주의 ERP 데이터와 구조적 적합성 높음
  • Report Painter / BW로 상대적으로 구현 용이
  • 실무 채택 빈도 압도적으로 높음
단점
  • 현금 유입/유출 원천이 직접 보이지 않음
  • 비현금 조정 항목 누락 시 오류 발생
  • 운전자본 계정 분류 설계에 주의 필요

📘 매출 발생 → 현금 수취 (발생주의 vs 현금주의 차이) ▼
① 매출 인식 시점 (발생주의)
// 전기유형: RV (Invoice)
DR 매출채권 (AR)      50,000
  CR 매출 (Revenue)    50,000
// → 현금흐름 없음 (발생주의)
② 현금 수취 시점
// 전기유형: DZ (Customer Payment)
DR 은행 (Bank GL)     48,000
  CR 매출채권 (AR)    48,000
// → 직접법: Bank GL 및 관련 Clearing 정보를 기반으로 고객수취 현금을 식별·집계
// → 간접법: 채권증가 2,000으로 조정
직접법/간접법 데이터 추출 차이
직접법: Bank GL 계정의 DZ 전기유형 합산 → 48,000 직접 집계
간접법: 매출 50,000(P&L) - 매출채권 증감 2,000(B/S) = 48,000 역산

① 매입 인식 (Invoice)
// 전기유형: KR (Vendor Invoice)

  CR 매입채무 (AP) 31,000
// → 재고증가 1,000 포함

감가상각 전기
// 전기유형: AF (Depreciation)

간접법에서의 처리
왜 가산하는가
당기순이익 계산 시 비용으로 차감된 2,000이 실제로는 현금 유출이 아니므로, 다시 가산하여 영업활동 현금흐름을 복원합니다.

직접법에서는 감가상각비 계정을 집계하지 않습니다. Bank GL 기준으로 집계하므로 자동으로 제외됩니다.
📘 유형자산 취득 — 투자활동 현금흐름 ▼
// 전기유형: AA (Asset Acquisition)
DR 유형자산 (Asset GL)       5,000
  CR 은행 (Bank GL)          5,000

// FI-AA 연계: ANLA 테이블에 자산 마스터 생성
// BSEG: KOART = 'A' (Asset), ANLN1 = 자산번호
// → 투자활동으로 분류: Bank CR + KOART='A' 조건 필터
⚠ 설계 주의사항
자산 취득이 할부·리스인 경우 Bank 계정이 움직이지 않습니다. IFRS 16 적용 시 ROU 자산 취득은 비현금 투자활동으로 별도 공시해야 합니다.
03
Technical Deep Dive
현금흐름표 항목별 FI 원장 매핑
이 섹션의 목적
현금흐름표 각 라인 항목이 SAP FI 원장(BSEG / BKPF / 보조원장)의 어떤 필드, 어떤 전기유형, 어떤 계정과 대응되는지를 체계적으로 정리합니다. 이 매핑이 직접법/간접법 구현의 기술적 출발점입니다.
3-1   현금 및 현금성자산 식별 ▼

현금흐름표의 출발점은 현금 및 현금성자산의 범위를 정의하는 것입니다. SAP에서는 특정 GL 계정 그룹으로 관리합니다.

3-3   투자활동 현금흐름 — FI-AA 연계 매핑 ▼

투자활동은 FI-AA(자산회계) 모듈과의 연계가 핵심입니다. Bank 계정 움직임과 자산 테이블을 Join하여 추출합니다.

FI-AA 연계 테이블 구조
// 자산 취득 식별 쿼리 (개념)
SELECT BSEG.DMBTR, BSEG.SHKZG
FROM BSEG
INNER JOIN ANEP -- Asset Line Items
  ON BSEG.ANLN1 = ANEP.ANLN1
WHERE BSEG.KOART = 'A' -- 자산 계정유형
  AND ANEP.ANBTR > 0 -- 취득 금액
  AND BSEG.SAKNR IN ('Bank GL 범위')

Root Cause Analysis
SAP 표준 기능만으로 현금흐름표를 완성하기 어려운 이유
핵심 명제
SAP FI는 발생주의(Accrual Basis) 기반으로 설계된 시스템입니다. ECC 시절부터 Report Painter, FSV 기반 예제 리포트 등 표준 도구가 존재하지만, 현금흐름표는 현금주의 관점의 재분류와 다중 모듈 데이터 통합을 요구하며 — 이 구조적 복잡성이 표준 기능만으로 완성하기 어려운 근본 원인입니다.
① 발생주의 원장의 설계 철학

SAP FI의 모든 전기는 경제적 사건 발생 시점에 기록됩니다. 대금 수수 여부와 무관하게 매출·비용이 인식됩니다.

매출 인식
≠
현금 수취
비용 인식
≠
현금 지급

현금흐름표는 이 둘의 차이를 계산하는 작업이므로 단순 조회로 완성되지 않습니다.

② 현금흐름 분류 기준의 부재

FI 원장에는 거래의 현금흐름 분류(영업/투자/재무)를 저장하는 표준 필드가 없습니다.

  • GL 계정은 B/S / P&L 관점으로만 설계
  • 이자·배당의 분류는 기업 회계정책에 따라 다름
  • 동일 계정이 상황에 따라 다른 활동으로 분류될 수 있음
  • 섹션 3에서 확인한 복수 분류 케이스가 표준화를 방해
③ 시스템 분리 구조

현금흐름표 작성에 필요한 데이터가 복수 모듈에 분산되어 있습니다.

④ 간접법만 존재하는 표준 도구

SAP은 ECC 시절부터 Report Painter, FSV 기반 Cash Flow Statement 예제 리포트 등 표준 도구를 제공합니다. 다만 이들은 간접법 중심의 보조 도구이며, 기업별 계정 설계와 매핑 작업 없이는 즉시 활용이 어렵습니다.

  • Report Painter (GRR1~3): FSV 기반 간접법 레포트 설계 가능. 단, 수동 계정 배정 필요
  • FAGLF03 / S_ALR_87012271: GL 잔액 조회. 현금흐름 분류 기능 없음
  • SAP BPC / GR: 간접법 데이터 수집·연산 가능. 직접법은 별도 설계 필요
결론
직접법을 요구하는 고객사는 커스텀 개발 또는 별도 솔루션이 필수입니다.
📌 Section 3–4 핵심 요약
현금흐름표 구현의 핵심 난이도는 Bank 계정을 찾는 것이 아니라, 하나의 현금거래를 영업·투자·재무활동으로 정확히 분해하는 데 있다. KOART 조건, Clearing 추적, 리스 원금/이자 분리, IAS 7 정책 선택 — 이 모든 설계 과제가 그 분해 작업의 일부입니다.
📌 핵심 관점
현금흐름표는 재무상태표와 손익계산서를 단순 조회하는 보고서가 아닙니다. 발생주의 데이터를 현금주의 관점으로 재구성하는 "계산 결과물"입니다. 이것이 SAP 표준 기능만으로 완성하기 어려운 본질적 이유이며, 구축 프로젝트에서 별도 설계 공수가 필요한 근거입니다.

Q1. 간접법에서 감가상각비를 당기순이익에 '가산'하는 이유는?
감가상각비가 현금 유입이기 때문에
당기순이익 산정 시 차감된 비현금 비용을 복원하여 영업현금흐름을 역산하기 위해
IAS 7에서 감가상각비를 항상 가산하도록 규정했기 때문에
SAP FI에서 감가상각 전기가 Bank 계정을 차변으로 처리하기 때문에
감가상각비는 현금 유출이 없는 비현금 비용입니다. 당기순이익 계산 시 비용으로 차감되었지만, 실제로 현금이 나간 것이 아니므로 영업활동 현금흐름 역산 시 다시 가산합니다.
Q2. SAP FI에서 BSEG.KOART = 'A'가 의미하는 것은?
고객(Debtor) 계정
공급자(Creditor) 계정
자산(Asset) 계정 — 투자활동 식별의 대표적인 단서
재료(Material) 계정
KOART(계정 유형): D=고객, K=공급자, S=G/L, A=자산, M=재료. KOART='A'는 투자활동 식별에 활용되는 주요 조건 중 하나이며, 금융상품·대여금·투자부동산 등은 별도 GL 조건이 필요합니다.
