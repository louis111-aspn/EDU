연결 재무제표의 본질

연결 재무제표는 법적으로 독립된 복수의 법인을 단일 경제적 실체(Single Economic Entity)로 보고, 그룹 전체의 재무 상태를 표시한다.
별도 재무제표 관점
각 법인은 독립적 법인격을 기준으로 재무제표를 작성
🏢 A사 (모회사) — 별도 F/S
🏢 B사 (자회사) — 별도 F/S
🏢 C사 (자회사) — 별도 F/S
A→B 내부 매출이 A의 매출과 B의 매입에 각각 계상됨 → 단순 합산 시 과대 계상
연결 재무제표 관점
그룹 전체를 하나의 기업으로 보고 외부 거래만 표시
🌐 그룹 전체
A + B + C = 단일 실체
내부거래 → 제거 / 외부 거래만 표시
A→B 내부 매출은 그룹 내부의 자금 이동 → 연결 손익에 영향 없음
핵심 원칙: 내부거래를 제거해야 하는 이유
① 손익 과대계상 방지
그룹 내 매출이 외부 매출처럼 계상되면 연결 매출·이익이 실제보다 부풀려짐
② 자산 과대계상 방지
내부 양도된 자산의 미실현이익이 포함되면 연결 자산이 실제보다 크게 표시됨
③ 채권·채무 상호 상계
그룹 내 채권·채무는 외부 관계가 아니므로 연결 재무상태표에 표시하지 않음

유형 2: 매출·매입 — 진행률 산정 차이 (총예정원가 추정 상이)

양사 모두 투입법을 적용하지만, 총예정원가에 대한 추정액이 달라 진행률과 인식 금액에 차이가 발생한다. 방법론이 아닌 추정의 차이가 원인이며, 그룹 단일 추정 기준 합의가 근본 해결책이다.
거래 개요 및 진행률 계산 비교
A사
시공 법인
→
그룹 내 도급 계약
12월 말 기준 발생원가 700 (양사 동일)
→
B사
발주 법인
A사 (시공 법인):
발생원가 700 / 총예정원가 추정 1,000
진행률 700 ÷ 1,000 = 70%
용역매출 = 계약금액 × 70% = 700
B사 (발주 법인):
발생원가 700 / 총예정원가 추정 1,167
진행률 700 ÷ 1,167 = 60%
용역비 = 계약금액 × 60% = 600
불일치: 발생원가는 양사 동일(700)하나 총예정원가 추정 차이(1,000 vs. 1,167)로 진행률 상이(70% vs. 60%) → 인식 금액 차이 100 발생.
이 유형이 실무에서 발생하는 상황: 시공 법인(A사)은 현장 원가 정보를 직접 보유하여 총예정원가를 정밀 추정하는 반면, 발주 법인(B사)은 계약 초기 견적 또는 별도 추정 모델을 사용하여 총예정원가를 다르게 산정하는 경우. M&A 직후 피인수 법인의 추정 모델이 그룹 기준과 상이할 때도 발생.
A사 (시공) — 총예정원가 1,000 추정
기말 인식 분개 (진행률 70%)
(차) 매출채권 700 (대) 용역매출 700
발생원가 700 / 총예정원가 1,000 = 70%
B사 (발주) — 총예정원가 1,167 추정
기말 인식 분개 (진행률 60%)
(차) 용역비 600 (대) 매입채무 600
발생원가 700 / 총예정원가 1,167 = 60%
핵심: 투입법이라는 방법은 동일. 총예정원가 추정액(1,000 vs. 1,167)만 다름 → 진행률 차이(70% vs. 60%) → 인식 금액 차이 100. 어느 추정이 더 합리적인지 판단이 핵심.
유형1(Cut-off)과의 본질적 차이: Cut-off는 한쪽이 미계상(0). 이 유형은 양쪽 모두 계상하되 금액만 다름(700 vs. 600). 오류가 아닌 추정의 차이이므로 어느 숫자가 맞는지 회계적 판단이 선행되어야 함.
Case A: A사 추정(총예정원가 1,000, 진행률 70%) 채택 — B사 상향 조정
1 B사 수정 — 총예정원가 1,167 → 1,000으로 재산정, 차이분 100 추가 계상
(차) 용역비(비용) 100 (대) 매입채무 100
차변 100 = 대변 100. B사 용역비 600 → 700, 매입채무 600 → 700으로 증액. 양사 700 = 700 대칭 확보.
2 연결 워크시트: Elimination (700 기준)
(차) 용역매출 700 ← A사 내부 매출 전액 제거 (차) 매입채무 700 ← B사 IC 채무 전액 제거 (대) 매출채권 700 ← A사 IC 채권 전액 제거 (대) 용역비 700 ← B사 비용 전액 제거
차변 1,400 = 대변 1,400. 연결 손익 영향 없음 (용역매출 △700 = 용역비 △700).
채택 근거: 시공 법인(A사)이 현장 원가 정보를 직접 보유하므로 총예정원가 추정이 더 정밀. 통상 시공 법인 기준 채택이 합리적이나, 그룹 정책으로 사전 결정 필요.
Case B: B사 추정(총예정원가 1,167, 진행률 60%) 채택 — A사 하향 조정
1 A사 수정 — 총예정원가 1,000 → 1,167로 재산정, 차이분 100 감액
(차) 용역매출 100 ← A사 과대 인식분 환입 (대) 매출채권 100 ← 대응 채권 감액
차변 100 = 대변 100. A사 용역매출 700 → 600, 매출채권 700 → 600으로 감액. 양사 600 = 600 대칭 확보.

ICMR 필요성 및 보유 정보

ICMR은 양사 거래 데이터를 건별로 매칭하여 불일치 사유를 분류하고 조정 분개를 생성할 수 있는 유일한 도구다.
ICMR 조정의 경계 원칙 — 반드시 먼저 이해해야 할 전제
"ICMR 조정은 기본적으로 연결 레벨 adjustment이며, 개별 법인의 원장 자체를 수정하지 않는다."
GR Adjustment 성격 (기본)
ICMR이 생성하는 분개는 연결 워크시트(Group Journal) 위에서만 존재. 법인 ERP의 FI 원장에는 어떠한 전표도 생성되지 않음.
FI 전표 생성 옵션 (확장)
SAP GR은 ICMR 조정 분개를 법인 FI 모듈에 직접 전표로 생성하는 기능도 지원. 연결팀 판단 하에 법인 FI에 posting하여 원장 수준에서 불일치를 해소하는 방식. 단, 이 경우 법인 별도 재무제표에도 영향이 미치므로 법인 CFO 승인 필요.
Local GAAP 책임 분리
FI 전표 생성 여부와 무관하게, 근본 오류(T5 누락 등)는 반드시 법인에 피드백 → 다음 결산에서 법인 주도 수정 유도.
두 방식 비교: 연결 레벨 조정(Group Journal)은 법인 원장 불변·연결 마감 신속, FI 전표 생성은 법인 원장 수준 정확성 확보·감사 추적 강화. 불일치 규모·반복성·법인 협조 가능성에 따라 선택.

사유별 조정 분개 생성 로직

ICMR이 분류한 5가지 사유 각각에 대해 사전 정의된 분개 템플릿을 적용하여 Off-set 잔액을 완전히 해소한다.
전제 — ICMR 조정 분개의 두 가지 처리 방식:
① 연결 레벨 처리 (기본)

② FI 전표 생성 (확장 옵션)
SAP GR이 ICMR 조정 분개를 법인 FI에 직접 posting 지원. 법인 원장 수준 정확성 확보. 법인 CFO 승인 필요. 법인 별도 F/S에도 반영됨.

T3 특성: 금액은 동일하나 계정과목이 다름 — A사는 매출채권(자산)으로 계상했는데, B사는 입금 원인 미파악으로 가수금(부채)으로 임시 처리. 실무에서 매 결산 시 빈번하게 발생. ICMR 건별 매칭으로만 탐지 가능.
T3: 과목 차이 — 매출채권(A사) vs. 가수금 임시 계상(B사)
상황 A사가 B사에 상품 500 판매. A사는 매출채권 계상, B사는 입금 원인 미파악으로 가수금 임시 처리.
A사 (매출 법인): (차) 매출채권 500 (대) 매출 500 B사 (매입 법인) — 가수금 임시 처리: (차) 현금 500 (대) 가수금 500 ← 매입채무여야 하는데 원인 미파악으로 가수금 임시 계상
A사 매출채권 500 ↔ B사 매입채무 0. 금액은 같으나 B사 계정이 매입채무(부채) 대신 가수금(부채)으로 임시 처리. 잔액 기준으로는 양사 모두 부채이므로 금액 차이가 없어 일반 규칙으로 탐지 불가 — ICMR 건별 매칭만 가능.
분개 1 ICMR 생성 — B사 재분류 (가수금 → 매입채무)
(차) 가수금(B사) 500 ← 임시 계정 가수금 제거 (대) 매입채무(B사) 500 ← 경제적 실질(매입채무)로 확정
차변 500 = 대변 500. 가수금(임시 부채)을 소멸시키고 매입채무(확정 부채)로 전환. 이로써 A사 매출채권(자산) ↔ B사 매입채무(부채) 대칭 구조 확보.
분개 2 손익 + B/S Elimination
(차) 매출 500 ← A사 내부 매출 제거 (차) 매입채무 500 ← B사 IC 채무 제거 (대) 매출채권 500 ← A사 IC 채권 제거 (대) 매입(매출원가) 500 ← B사 내부 매입 제거
차변 1,000 = 대변 1,000. 분개 1로 B사 계정이 정렬된 후 표준 Elimination. 연결 손익 영향 없음 (매출 △500 = 매입 △500).
핵심 원칙 — ICMR이 T3에서 하는 일 "ICMR은 먼저 거래 성격(Classification)을 정렬한 후, Elimination을 수행한다."
① 왜 재분류가 먼저인가 — 가수금과 매입채무는 둘 다 부채이므로 금액 합산만으로는 불일치 탐지 불가. ICMR의 계정명 매칭만이 탐지 가능
② 실무 발생 빈도 — B사 경리팀이 IC 입금 원인을 즉시 파악하지 못하고 가수금 임시 처리 후 방치하는 케이스가 연결 마감 시 빈번히 발생
③ GR 표준 Elimination 한계 — 표준 태스크는 매출채권 ↔ 매입채무 계정 대칭을 전제. 매출채권 ↔ 가수금 조합은 탐지·정렬 불가
T4 특성: 동일 방법(투입법)을 적용하지만 총예정원가 추정액이 달라 진행률·인식 금액이 상이. 오류가 아닌 추정의 차이이므로 어느 추정이 합리적인지 회계적 판단이 선행되어야 함.
T4: 측정 차이 — 총예정원가 추정 상이로 인한 진행률 차이
상황 동일 IC 도급 계약. 발생원가 700 동일. 총예정원가 추정액만 상이 → 진행률·인식 금액 차이 100 발생.
A사 (시공): 총예정원가 1,000 추정 → 진행률 70% → 용역매출 700 (차) 매출채권 700 (대) 용역매출 700 B사 (발주): 총예정원가 1,167 추정 → 진행률 60% → 용역비 600 (차) 용역비 600 (대) 매입채무 600
투입법으로 방법 동일. 발생원가(700)도 동일. 총예정원가 추정(1,000 vs. 1,167)만 달라 진행률(70% vs. 60%), 인식 금액(700 vs. 600) 차이 발생. ICMR이 차이 100을 탐지.
분개 1 ICMR 생성 — A사 추정 채택 시 B사 차이분 조정
(차) 용역비(비용) 100 ← B사 과소 계상분 추가 인식 (대) 매입채무 100 ← 대응 채무 추가 계상
차변 100 = 대변 100. 그룹 기준(A사 추정 700) 채택 시 B사 차이분 100 조정. 양사 700 = 700 대칭 확보 후 표준 Elimination 가능.
분개 2 이후 표준 Elimination (700 기준)
(차) 용역매출 700 (차) 매입채무 700 (대) 매출채권 700 (대) 용역비 700
차변 1,400 = 대변 1,400. 연결 손익 영향 없음 (용역매출 △700 = 용역비 △700).
T4의 핵심: 어느 추정이 더 합리적인지 판단이 선행되어야 조정 방향이 결정됨. 시공 법인(A사)이 현장 원가 정보를 직접 보유하므로 통상 A사 추정 채택이 합리적. 그룹 정책으로 사전 결정 필요.
T5 특성: 가장 강도 높은 불일치 — 일방이 아예 미계상. 계상 법인 데이터 기준으로 상대방 분개 강제 생성.
T5: 누락 — 계상 법인 기준 강제 생성 분개
상황 A사 IC 매출 100 계상, B사 IC 매입 및 채무 전혀 미계상
분개 1 ICMR 생성 — B사 매입 전체 강제 계상
(차) IC 매입원가(B사) 100 (대) IC 매입채무(B사) 100
차변(매입원가): 비용 발생 인식 / 대변(매입채무): 부채 생성(증가). 연결 레벨에서 B사에 매입원가와 매입채무를 동시에 강제 계상. 이후 Elimination에서 A사 매출채권과 B사 매입채무를 상계, A사 매출과 B사 매입원가를 상계하여 전액 제거.
분개 2 이후 표준 Elimination
(차) IC 매출 100 (차) IC 매입채무 100 (대) IC 매출채권 100 (대) IC 매입원가 100
T5는 법인의 근본적 데이터 오류. 연결 조정 후 반드시 해당 법인에 피드백하여 다음 결산에서 FI 레벨 수정 유도.

ICMR 기반 전체 처리 아키텍처

ICMR 실행 → 사유 분류 → 조정 분개 자동 생성 → Elimination → Off-set 잔액 = 0 검증의 5단계가 연결 마감의 핵심 루틴이다.

GR/IR
GR/IR Clearing 계정 활용: B사가 물품 미수령 상태에서도 Invoice 수령 시 GR/IR Clearing 계정으로 임시 계상 → 수령(GR) 시 자동 정리. Cut-off 차이 구조적 방지.
Auto Post
자동분개 설정: MM-FI 연동 시 GR 시점에 자동으로 매입채무 계상되도록 Posting Key 및 Account Determination 설정
Period
기간 통제: 결산 월 마감 후 전기 기간(Prior Period Posting) 허용 여부를 권한 그룹(Authorization Group)으로 통제하여 임의 소급 방지

VF44
Revenue Recognition: SD 모듈과 FI 연동하여 진행률 기준 수익 자동 인식 설정. VF44 트랜잭션으로 월별 수익 인식 자동 처리.
PS-FI
PS 모듈 연동: 용역 프로젝트 진행률을 PS(Project System) 모듈에서 관리하고 FI 자동분개 트리거. 진행률 데이터 단일 소스 관리.

Intercompany Billing 자동화: IC 거래에 대해 SD-FI 자동 Invoice 생성 → 양사 동시 계상 구현. 수동 청구서 발행 오류 제거.
FAGL
외화 자동 재환산(FAGL_FC_VAL): 기말 화폐성 항목(미수·미지급배당금)을 기말환율로 자동 재환산. 양사 동일 환율 적용으로 T1 차이 최소화.
GR
연결 환산 모듈: 해외 자회사 재무제표 환산 시 화폐성/비화폐성 항목별 환율 자동 적용. 해외사업환산차이(OCI) 자동 계산 및 P/L 외환차익과 상쇄 처리.
TP
Trading Partner: 모든 IC 배당 전표에 Trading Partner 필수 입력. ICMR에서 환율 차이(T1) 자동 탐지 및 OCI 흡수 분개 자동 생성.

GR

DTax
이연법인세 자동 계산: TAX 모듈과 연동하여 미실현이익 제거에 따른 임시차이 발생 시 이연법인세 자동 분개.
GR

DTax

GR 처리 핵심 원칙 — 3줄 요약
GR Elimination의 본질
"제거(Elimination)"이지 "조정(Correction)"이 아니다. Off-set 잔액 노출은 버그가 아닌 의도된 설계.
불일치 해소의 원칙
법인이 먼저, 연결이 나중. 마감 전이면 법인 FI 수정, 마감 후면 ICMR 조정 분개.
ICMR의 역할과 한계
분류 정렬 + 조정 분개 자동 생성으로 Off-set 잔액 = 0 강제. 단, 데이터 품질과 IC Governance 자체를 대체하지 않는다. Tool은 보조 수단.
