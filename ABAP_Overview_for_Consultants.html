01 · History & Evolution

ABAP의 진화: 메인프레임 언어에서
클라우드 네이티브 프레임워크까지

ABAP은 40년간 SAP 시스템의 핵심 개발 언어로 자리잡았으며, S/4HANA 전환과 함께 RAP 모델로의 패러다임 전환이 진행 중임 — 컨설턴트는 이 세대 차이를 이해해야 고객 현황을 정확히 진단할 수 있음

1983 – 1990s
Classic ABAP: Procedural 시대
SAP R/2, R/3와 함께 등장. FORM/PERFORM 구조, 모듈풀, 배치 프로그램 위주. 독일어 기반 키워드가 혼용됨.
FORM/PERFORM ALV Report BDC
2000s
ABAP Objects: 객체지향 도입
Class/Interface 개념 도입. Design Pattern 적용 가능. 단 기존 절차적 코드와 혼재하여 "ABAP OO"와 "Classic"이 공존하는 과도기.
CLASS/METHOD INTERFACE BADI
2010s
ABAP for HANA: DB 밀착 최적화
SAP HANA 인메모리 DB 도입으로 "Code to Data" 패러다임 전환. Open SQL 확장, CDS View 등장, AMDP(ABAP Managed Database Procedure) 도입.
CDS View AMDP Open SQL
2019 ~
RAP: RESTful Application Model
SAP S/4HANA Cloud 전략의 핵심. OData 서비스를 선언적으로 생성, Fiori Elements UI 자동화, ABAP on BTP까지 확장.
RAP OData v4 Fiori Elements ABAP Cloud

ABAP 개발 생태계 전체 구조

03 · Strengths & Weaknesses

ABAP이 강한 것과 약한 것:
컨설턴트가 알아야 할 현실

ABAP은 SAP 비즈니스 로직 구현에 최적화된 언어이나, 범용 소프트웨어 개발 언어와 비교시 명확한 한계가 존재함 — 이를 인식해야 현실적인 개발 범위와 일정을 협의할 수 있음

▲
ABAP이 탁월한 영역
SAP 표준 데이터 직접 접근
수천 개의 SAP 표준 테이블(BKPF, EKKO, VBAK 등)을 직접 Open SQL로 조회·조작. 별도 API 없이 핵심 비즈니스 데이터에 완벽 접근.
BAPI / 표준 함수 모듈 활용
SAP이 제공하는 수천 개의 검증된 BAPI를 재사용. 전표 생성, 자재이동 등 복잡한 비즈니스 트랜잭션을 함수 호출 하나로 처리.
내부 테이블(Internal Table) 처리
ABAP 고유의 강력한 데이터 컨테이너. 대용량 데이터 정렬, 집계, 조인을 메모리에서 고속 처리. 복잡한 보고서 개발에 탁월.
Enhancement Framework (수정 최소화)
BAdI, Enhancement Point, User-Exit으로 SAP 표준 코드 원본을 건드리지 않고 커스터마이즈. SAP 업그레이드 시 수정사항 보존.
대용량 배치 처리
수백만 건의 데이터를 처리하는 배치 프로그램, 병렬처리(Parallel Processing), 백그라운드 잡(Job) 관리에 최적화된 설계.
다국어·다통화 글로벌 지원
텍스트 요소 분리, 다국어 메시지 클래스, 통화·단위 변환 함수 내장. 글로벌 기업의 다국가 배포에 설계 단계부터 최적화.
▼
ABAP의 구조적 한계
인재 공급 부족 · 고령화
ABAP 개발자 풀이 협소하고 고령화. 신규 개발자 유입 제한. 결과적으로 고용 비용 상승, 긴 채용 기간, 지식 의존 리스크 증가.
현대적 UI/UX 개발 비적합
SAP GUI는 구식. Fiori 개발은 ABAP+JavaScript 분리 구조로 복잡도 증가. React/Vue 수준의 리치 인터랙션 구현에는 한계.
외부 시스템 통합의 복잡성
SAP 외부 API 호출(REST/GraphQL)이 근본적으로 불편. HTTP Client 클래스를 수동 구성해야 함. 단순 REST 연동도 클래스 10개 이상 필요.
DevOps · CI/CD 생태계 미성숙
Git 기반 버전관리(gCTS)는 발전 중이나 현장 도입률 낮음. 자동화 테스트, 배포 파이프라인 구성이 일반 SW 대비 훨씬 복잡.
SAP 외 환경에서 완전 무용
ABAP 기술은 SAP 시스템에서만 작동. 이직·전직 시 기술 이전성 낮아 개발자 이탈 시 지식 소멸 위험. 오픈소스 생태계 연계 불가.
레거시 코드의 기술 부채
20~30년 된 절차적 Classic ABAP 코드가 현업에서 여전히 운용. 리팩터링 없이 패치만 반복되어 이해·유지보수 비용이 기하급수적 증가.
업무 유형별 ABAP 적합성 평가
개발 유형 ABAP 적합도 근거 및 컨설턴트 시사점

RAP 핵심 개념 FAQ
RAP와 기존 OData(SEGW) 방식의 차이는? ▼
SEGW는 수동으로 OData 엔티티·매핑을 작성해야 했으나, RAP는 CDS Annotation 기반으로 OData 서비스가 자동 생성됩니다. 코드량이 60~70% 감소하고, UI 레이아웃도 Annotation으로 선언적 제어 가능합니다.
Managed vs Unmanaged RAP의 차이는? ▼
Managed: SAP 프레임워크가 CRUD 로직(save, lock, draft)을 자동 처리. 단순 마스터데이터 유지보수에 적합. Unmanaged: 개발자가 모든 데이터 처리 로직을 직접 구현. 복잡한 비즈니스 로직이나 외부 시스템 연동 시 선택.
Draft 기능이란? ▼
사용자가 저장 전 입력 중인 데이터를 임시 저장하는 기능. RAP는 Draft 테이블 관리를 프레임워크가 자동 처리. Fiori 앱에서 페이지 이탈 후 재접속 시 작업 내용 복원 가능.
RAP에서 권한 체크는 어떻게? ▼
Behavior Definition에서 Authorization Master를 선언하고, ABAP 클래스에서 IS_AUTHORIZED 메서드를 구현합니다. CDS 레벨의 DCL(Data Control Language)과 결합하여 행 레벨 권한도 구현 가능합니다.
ABAP Cloud (BTP)에서의 제약은? ▼
ABAP Cloud에서는 Released API(SAP가 공개한 API)만 호출 가능. 내부 SAP 함수 모듈 직접 호출 불가. 이 제약으로 인해 기존 ECC 코드의 BTP 마이그레이션 공수가 과소 추정되는 경우가 많음 — 이 점을 고객에게 반드시 설명해야 함.

" 주문 관리 RAP 정의 예시 managed implementation in class zbp_order_header unique; define behavior for ZI_OrderHeader alias OrderHeader persistent table zorder_h draft table zorder_h_d lock master total etag ChangedAt { // CRUD 자동 관리 create; update; delete; // 커스텀 액션 (버튼) action Approve result [1] $self; action Reject result [1] $self; // 검증 로직 validation checkAmount on save { create; update; } // 자식 엔티티 association _Items { create; } }
05 · Consultant Communication Guide

개발자와 효과적으로 협의하기 위한
10가지 핵심 질문과 맥락

컨설턴트가 ABAP 개발자와 협업 시 올바른 질문을 통해 공수·리스크·기술 부채를 정확히 파악해야 클라이언트에게 현실적인 가이드를 제공할 수 있음

01
"이 요건, Enhancement로 가능합니까 아니면 수정(Modification)입니까?"
Enhancement는 SAP 표준을 건드리지 않아 업그레이드 안전. Modification은 SAP 업데이트 시 재작업 필요. 대규모 롤아웃 계획 있다면 반드시 확인.
BAdI vs. Source Code Modification
02
"Z 테이블을 새로 만드나요, 표준 테이블에 Append Structure를 추가하나요?"
커스텀 테이블(Z/Y prefix) 생성은 유연하지만 표준 보고서 연계 누락 위험. Append Structure는 표준 테이블 확장으로 통합 용이하나 제약 존재.
Data Model Design
03
"CDS View로 개발합니까, 아니면 ABAP 코드에서 직접 SELECT합니까?"
CDS View는 재사용성·성능 우수하나 초기 설계 시간 필요. 직접 SELECT는 빠르지만 유지보수 부채 증가. S/4HANA 환경이라면 CDS 권장.
CDS vs. Open SQL
04
"ABAP Unit Test 작성을 계획에 포함했나요?"
테스트 코드 미작성 시 회귀 버그 위험 증가. SAP은 Test Double Framework 제공. 공수의 20~30% 추가 필요하나 장기적 유지보수 비용 절감.
ABAP Unit / Test Double
05
"성능 테스트(HANA Trace)는 어느 시점에 계획되어 있나요?"
ABAP 개발의 가장 큰 숨은 리스크. SELECT * FULL SCAN 하나가 시스템 전체를 마비시킬 수 있음. 개발 완료 후가 아니라 개발 중 주기적 체크 필요.
ST05 / HANA Trace
06
"이 인터페이스, ABAP에서 직접 호출합니까 아니면 Integration Suite를 거칩니까?"
ABAP에서 직접 외부 REST 호출 시 에러 처리·인증·모니터링 부담. BTP Integration Suite(iFlow)를 허브로 사용하면 운영 가시성 대폭 향상.
PI/PO vs. BTP Integration
07
"이 개발, Transport Request는 어떻게 관리하나요?"
SAP 변경관리는 TR(Transport Request) 기반. DEV→QAS→PRD 이동. TR 의존성 관리 실패 시 기능 배포 순서 오류로 운영 장애 발생 가능.
CTS / Transport Management
08
"S/4HANA Cloud입니까, On-premise입니까? Public Cloud입니까?"
S/4HANA Public Cloud는 ABAP Cloud 제약(Released API만). On-premise/Private Cloud는 Classic ABAP 전부 가능. 개발 자유도가 근본적으로 다름.
Deployment Model
09
"RAP로 개발합니까, 아니면 기존 방식입니까?"
RAP는 S/4HANA 1909+에서 가능. Fiori Elements와의 통합, 미래 업그레이드 친화성 측면에서 RAP 권장. 단 팀의 RAP 역량 확인 필수.
RAP vs. SEGW/Classic
✓ 개발자와 소통 시 이렇게 하세요
  • 📋 기능 단위로 개발 범위를 명확히 문서화 (Functional Spec)
  • 🏷️ Z/Y prefix 커스텀 오브젝트 현황을 초기에 파악
  • 📊 성능 영향도가 큰 기능은 데이터 볼륨을 반드시 명시
  • 🔄 Enhancement 우선, 수정(Modification)은 최후 수단
  • 📅 Transport 일정을 배포 계획에 반드시 포함
  • 🧪 테스트 시나리오를 functional spec 수준으로 사전 준비
✗ 이런 오해는 피하세요
  • ❌ "ABAP은 구식 언어라 빠르게 만들 수 있다" → 도메인 복잡도 고려 필수
  • ❌ "SAP 표준에 있으니 바로 쓸 수 있다" → 설정·커스터마이즈 공수 별도
  • ❌ "ECC 코드 그대로 S/4로 이전된다" → ABAP Cloud 제약으로 재개발 필요
  • ❌ "API 연동은 ABAP에서 간단하다" → 외부 연동은 Integration Suite 권장
  • ❌ "개발자 1명이면 충분하다" → 복잡한 RAP는 ABAP+UI5 이원 역량 필요
  • ❌ "테스트는 개발 완료 후에" → 배치·인터페이스는 초기부터 통합 테스트
06 · Glossary

ABAP 핵심 용어집:
개발자와 대화 시 알아야 할 40선

개발자가 사용하는 기술 용어를 이해함으로써 회의 효율을 높이고, 잘못된 scope 정의로 인한 재작업을 예방할 수 있음

Transparent Table
SAP DDIC에서 정의하는 기본 DB 테이블. 각 테이블이 DB에 1:1로 대응. 커스텀 Z테이블의 기본 유형.
Internal Table
ABAP 메모리 내 데이터 컨테이너. Hashed/Sorted/Standard 세 가지 유형. 성능의 핵심.
Data Dictionary (DDIC)
SAP 메타데이터 저장소. 테이블, 구조체, 데이터 요소, 도메인 정의. SE11 트랜잭션.
Domain / Data Element
Domain: 값 범위 정의. Data Element: 필드의 의미와 Label 정의. DDIC의 기본 단위.
CDS View (Core Data Services)
HANA 기반 재사용 가능한 데이터 뷰 계층. Annotation으로 UI·OData까지 제어.
Append Structure
SAP 표준 테이블에 커스텀 필드를 추가하는 방식. 표준 테이블 직접 수정 없이 확장.
Function Module (FM)
재사용 가능한 절차형 함수 단위. RFC 가능 여부 설정으로 원격 호출 지원. BAPI의 기반.
BAPI
Business API. SAP 표준 Function Module 중 비즈니스 오퍼레이션용. BAPI_ACC_DOCUMENT_POST 등.
BAdI (Business Add-In)
SAP 표준 코드 수정 없이 커스텀 로직 삽입하는 Enhancement 메커니즘. OO 기반.
User Exit / Enhancement Spot
구형 BAdI 전신. SUSR/CMOD 트랜잭션. 신규 개발에는 BAdI 사용 권장.
ALV (ABAP List Viewer)
SAP 표준 보고서 출력 프레임워크. 필터·정렬·엑셀 다운로드 자동 지원. 보고서의 90%가 ALV.
Dynpro (Screen)
SAP GUI 화면 정의 언어. Module Pool 프로그램의 UI. Flow Logic(PBO/PAI)으로 제어.
Selection Screen
보고서·배치 프로그램의 입력 파라미터 화면. PARAMETERS/SELECT-OPTIONS 문으로 선언.
ABAP Unit
ABAP 내장 단위 테스트 프레임워크. CLASS ... FOR TESTING. TDD 지원.
AMDP
ABAP Managed Database Procedure. ABAP 클래스 내에서 HANA SQLScript 실행. DB 레벨 성능 최적화.
Smartforms / Adobe Forms
SAP 출력 양식 도구. 송장, 납품서, 계약서 등 인쇄물. Adobe Forms가 현재 표준.
RFC (Remote Function Call)
SAP 시스템 간 또는 외부 시스템 연동 프로토콜. Synchronous/Async/Transactional(tRFC) 유형.
IDoc (Intermediate Document)
SAP 전자문서 표준 포맷. EDI, B2B 문서 교환. ORDERS, DESADV 등 표준 메시지 유형.
PI/PO (Process Orchestration)
SAP 미들웨어. 시스템 간 메시지 라우팅·변환. BTP Integration Suite로 진화 중.
OData Service
Fiori/모바일 앱 백엔드 REST 프로토콜. v2(SEGW 기반) / v4(RAP 기반). JSON/XML 지원.
RAP (RESTful Application Programming)
S/4HANA 표준 개발 방법론. CDS+Behavior Definition+OData의 통합 프레임워크.
Behavior Definition (BDEF)
RAP의 비즈니스 로직 선언 파일. CRUD, Action, Validation, Determination 정의.
Behavior Implementation Class
BDEF에서 선언한 로직을 구현하는 ABAP 클래스. Local Handler/Saver 포함.
Managed Scenario
RAP에서 프레임워크가 save/lock/draft를 자동 처리. 단순 마스터데이터에 적합.
Draft Handling
저장 전 임시 데이터 관리 기능. RAP 프레임워크가 Draft 테이블 자동 관리.
Fiori Elements
OData Annotation 기반 자동 생성 UI. List Report, Object Page 등 템플릿 제공.
ABAP Cloud
BTP ABAP Environment. Released API만 사용 가능. 테넌트 격리. 클라우드 네이티브 ABAP.
ADT (ABAP Development Tools)
Eclipse 기반 현대적 ABAP IDE. RAP 개발, 리팩터링, 코드 완성, 디버깅 지원.
Transport Request (TR)
개발 오브젝트를 DEV→QAS→PRD로 이동하는 패키지. SAP 변경관리의 기본 단위.
Workbench Request vs. Customizing Request
WR: 프로그램·DDIC 등 개발 오브젝트. CR: IMG 설정값. 혼용 금지.
ST05 / HANA Explain Plan
SQL 성능 분석 도구. DB 쿼리 실행 계획 확인. 풀 스캔·인덱스 누락 탐지.
SM37 / Background Job
백그라운드 배치 잡 관리. 스케줄링·모니터링. 대용량 처리의 핵심.
gCTS (Git-enabled CTS)
SAP Transport를 Git 저장소와 연동하는 기능. CI/CD 파이프라인 구성의 기반.
SPAM / Add-On Installation
SAP 지원 패키지 관리자. SAP 수정 패치 적용. 커스텀 코드와의 충돌 분석 필수.
SCC4 / Mandant
SAP 클라이언트(회사 코드와 다름). DEV/QAS/PRD 각각 독립된 Mandant 운영.
BDC (Batch Data Communication)
화면 자동화로 데이터 대량 입력. Legacy 시스템 데이터 마이그레이션에 활용.
LSMW / BAPI Migration
데이터 마이그레이션 도구. 현재는 BAPI 기반 또는 SAP Migration Cockpit 사용 권장.
Cluster Table / Pooled Table
여러 논리 테이블을 하나의 물리 DB 테이블에 저장. HR/FI 일부에서 사용. S/4에서 Transparent으로 전환.
VDM (Virtual Data Model)
S/4HANA CDS 뷰 아키텍처. Basic→Composite→Consumption 계층 구조.
BTP Integration Suite (iFlow)
SAP PI/PO의 클라우드 후계. 그래픽 기반 인터페이스 설계. REST·SOAP·IDoc 지원.
